# Clew UI — редизайн

Обсуждение и план переработки интерфейса. Фокус: быстрая навигация между задачами,
мгновенное понимание статуса, экран агентов с терминалами.

## Цели

1. Навигация по активным задачам через левый сайдбар со статусами на виду.
2. Экран задачи: заголовок (+ теги раздела), сворачиваемое описание, степпер прогресса.
3. Главный экран — агенты: слоты по профилю задачи (quick: worker; standard:
   worker + reviewer; deep: architect + workers + reviewer), терминал внутри
   приложения или во внешнем терминале.
4. Кнопка открыть изменения вовне (редактор/дифф).
5. Понимать статус задачи и «где мы находимся» за 1 секунду.

## Сайдбар

- Список задач слева, наверху — фильтры-чипы по статусу.
- Сортировка: требующие внимания сверху (Ожидает/Ошибка → активные → остальные).
- Лейблы статусов — на английском. Маппинг на `TaskState`:

| Лейбл     | Состояния                        | Цвет          |
| --------- | -------------------------------- | ------------- |
| Draft     | DRAFT                            | серый         |
| Plan      | PLAN_READY, QUEUED               | синий         |
| Executing | EXECUTING, RECOVERING, VERIFYING | синий (пульс) |
| Review    | REVIEWING                        | фиолетовый    |
| Waiting   | WAITING_FOR_HUMAN, BLOCKED       | amber         |
| Ready     | READY, COMPLETED                 | зелёный       |
| Failed    | FAILED, CANCELLED                | красный       |

- Строка задачи: статус-точка + лейбл, id, заголовок. Ожидание/ошибка визуально выделены.

## Экран задачи

- Заголовок + теги (к какому разделу относится). Фаза 1: используем `profile` как тег;
  фаза 2: поле `tags` в контракте задачи (схема + миграция).
- Описание (goal) — сворачиваемый блок, развёрнут по умолчанию.
- Степпер: Plan → Execute → Review → Ready; активный шаг подсвечен, причина
  внимания (attention) — прямо под степпером.
- Компактная строка метрик: ревизия, findings, попытки.

## Экран агентов (основной упор)

- Слоты динамические, по профилю задачи (`resolveProfile`, src/domain.js:309):
  - **quick**: worker (1);
  - **standard**: worker + reviewer;
  - **deep**: architect + до 3 workers + reviewer (+ integration-стадия).
- Роли уже есть в бэкенде: `SESSION_ROLES` (architect/worker/reviewer/qa),
  `clew session open --role`.
- Каждый слот показывает: активен ли ран, роль, харнес, последнюю активность.
- Действия на слот:
  - «Open terminal» (внешний) — уже работает (`session open`, macOS Terminal через
    osascript; live-режим для RUNNING через `task result --watch`).
  - «Open in window» — внутренний терминал, фаза 2.
- Фаза 2 (бэкенд): стриминг PTY в браузер — новый WS-эндпоинт в daemon + xterm.js в UI.
  Внимание: `docs/UI.md` декларирует «не рендерим сырой вывод» — для терминала нужно
  явное исключение и решение по безопасности.

## Изменения вовне

- Кнопка «Open changes» на экране задачи: открывает `run.workspace` последней ревизии
  в VS Code с диффом (например, `code --diff` / `code <workspace>` с фокусом на
  изменённых файлах). Реализация: новая команда/поверхность в `session-surface.js`
  или CLI-команда `clew task open --editor`.

## Визуальный стиль

- Тёмная тема в духе Linear: фон `#0d0d0d`, границы `#262626`, акцент `#5e6ad2`.
- Компактные плоские панели, квадраты со скруглением 6–8px, минимум теней.
- Пульсация/анимация только для активно исполняющихся шагов.

## Фазы работы

1. **Фаза 1 — редизайн UI + минимум бэкенда**:
   - редизайн сайдбара: статусы, фильтры, сортировка «внимание сверху»;
   - экран задачи: теги (профиль), сворачиваемое описание, степпер, метрики;
   - экран агентов: динамические слоты по профилю, кнопки внешнего терминала;
   - кнопка «Open changes» → VS Code: нужна небольшая команда в бэкенде
     (запуск `code <workspace>` из daemon, по аналогии с `session-surface.js`);
   - новая палитра/типографика (`styles.css`).
2. **Фаза 2**:
   - внутренние терминалы (PTY-стриминг + xterm.js);
   - теги задач в контракте (схема + миграция).

## Файлы

- Фаза 1: `ui/src/App.tsx` (разбить на компоненты), `ui/src/styles.css`,
  `ui/src/types.ts`, `ui/src/api.ts`, `ui/src/fixtures.ts`.
- Фаза 2: `src/daemon.js`, `src/session-surface.js`, `schemas/`, `migrations/`.

## Принятые решения

- Сортировка сайдбара: требующие внимания сверху (Ожидает/Ошибка → активные → остальные).
- «Открыть изменения»: VS Code с диффом (базово — `code <workspace>`, диффы видны в SCM).
- Слоты агентов динамические по профилю задачи (см. «Экран агентов»); роль `qa`
  пока не выносим отдельным слотом.
- Лейблы статусов — английский.
- Акцент — Linear purple `#5e6ad2`.

## Открытые вопросы

- Фаза 2: безопасность внутреннего терминала (сырой вывод в браузере) — отдельное
  обсуждение перед стартом.
