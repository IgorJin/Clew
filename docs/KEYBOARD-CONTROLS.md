# Управление Clew с клавиатуры

Статус: предложение. Дата: 2026-09-10. Релиз не назначен.

## Цель

Основные переходы и действия на экране задачи выполняются без мыши. Пользователь видит доступные сочетания, когда удерживает Command, и может открыть палитру для всего остального.

Сейчас реализованы только `Cmd/Ctrl+K`, навигация стрелками и Enter внутри палитры, а также Escape в модалках и popover. Остальные сочетания ниже пока являются планом.

## Карта сочетаний

На macOS используется `Cmd`, на Windows/Linux — `Ctrl`, если сочетание не занято платформой.

| Сочетание                  | Действие                                            | Область                            |
| -------------------------- | --------------------------------------------------- | ---------------------------------- |
| `Cmd+1` … `Cmd+9`, `Cmd+0` | Открыть соответственно 1–10-ю видимую задачу        | Список задач текущего проекта      |
| `Cmd+K`                    | Открыть глобальную палитру проектов и задач         | Везде                              |
| `Cmd+Enter`                | Выполнить контекстное Continue                      | Экран задачи                       |
| `Cmd+E`                    | Открыть внутреннюю модалку изменений                | Экран задачи при наличии diff      |
| `Cmd+Shift+E`              | Открыть изменения во внешнем viewer                 | Экран задачи при доступном adapter |
| `Cmd+\``                   | Раскрыть/сфокусировать встроенный активный терминал | Экран выполняющейся задачи         |
| `Cmd+Shift+\``             | Открыть активную сессию во внешнем терминале        | Экран задачи при доступной session |
| `Escape`                   | Закрыть верхнюю модалку, меню или key hints         | Текущий слой UI                    |

`Cmd+1…0` адресует список после текущего project scope, фильтра и фактической сортировки. Бейджи `1…9, 0` показываются у тех же строк. Изменение фильтра или сортировки сразу меняет привязку. Если нужной позиции нет, сочетание ничего не делает и не меняет выбранную задачу.

## Одна команда Continue

В UI остаётся одно основное контекстное действие `Continue`. Пользователь не выбирает между resume и restart: Clew использует сохранённую native-сессию, когда runtime подтверждает совместимое продолжение, и создаёт новый run/session, когда продолжение невозможно или явно требуется policy. Фактический выбор записывается в Task Thread.

Поведение `Cmd+Enter` по состоянию:

| Состояние                                         | Результат                                                                                       |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Worker ожидает текст в активном embedded terminal | Сфокусировать терминал; ничего не отправлять автоматически                                      |
| `READY` или исправимое `WAITING_FOR_HUMAN`        | Вызвать `continue`; runtime выбирает resume или fresh session                                   |
| Следующий шаг готов и требует подтверждения       | Открыть существующую confirmation modal; повторный `Cmd+Enter` внутри неё подтверждает действие |
| Worker выполняется и не ждёт пользователя         | Не выполнять управляющую команду                                                                |
| Действие недоступно                               | Показать disabled key hint с короткой причиной                                                  |

`Finish worker`, `Finish work`, merge и release не входят в `Cmd+Enter`. Завершение активного worker остаётся отдельным явным действием, чтобы привычный хоткей продолжения не мог случайно завершить работу.

Существующую header-кнопку нужно переименовать и упростить: `Continue` для продолжения, `Start` до первого запуска и `Focus terminal` при ожидании ввода. Технические слова `restart` и `resume` показываются в результате или Task Thread, а не требуют продуктового выбора до запуска.

## Терминалы

Сейчас controller-local активный терминал автоматически раскрывается на выбранной задаче и embedded UI подключается к существующему PTY. Внешний Terminal.app автоматически не запускается. Для Runner-local session UI сообщает, что открытие возможно на Runner host.

`Cmd+\`` повторяет безопасное локальное действие: раскрывает нужную agent card и переводит фокус в terminal. Если одновременно активны несколько ролей или stages, первое нажатие открывает компактный chooser; последующий выбор запоминается для этой задачи. Сочетание `Cmd+Shift+\``вызывает`TerminalLauncher` для выбранной активной session.

## Изменения

`Cmd+E` открывает существующий read-only diff modal для выбранного change run. Если у задачи несколько runs, используется уже выбранный в header run; при отсутствии выбора — последний релевантный run по тем же правилам, что и кнопка Changes.

`Cmd+Shift+E` передаёт этот же run во внешний `ChangeViewer`. Adapter обязан открыть точный диапазон baseline → result или честно вернуть ограничение. Простое открытие worktree в IDE является отдельным действием `Open workspace`, потому что чистый worktree может скрыть уже закоммиченные изменения.

## Key hints при удержании Command

После удержания `Cmd` примерно 180 ms UI показывает небольшие бейджи рядом со всеми зарегистрированными для текущего экрана действиями:

- `1…9, 0` возле первых десяти видимых задач;
- `↵` возле Continue/Start/Focus terminal;
- `E` и `⇧E` возле внутреннего и внешнего открытия изменений;
- `` ` `` и `` ⇧` `` возле встроенного и внешнего терминала;
- `K` возле входа в command palette.

Бейдж располагается поверх края элемента, не меняет layout и не перекрывает label. Недоступное действие получает приглушённый бейдж и короткую причину в tooltip. Overlay исчезает на `keyup`, `Escape`, потере фокуса окна и `visibilitychange`, чтобы не зависать после системного переключения приложения. Для устройств без Command доступна отдельная справка Keyboard shortcuts в палитре.

Сочетания объявляются в одном registry вместе с label, scope, predicate доступности и handler. Из этого registry строятся обработчики, key hints, tooltip и экран справки; текст на кнопках и фактическая команда не расходятся.

## Scope и приоритет

Приоритет обработки: открытая модалка → сфокусированный embedded terminal → экран задачи → глобальная навигация. В `input`, `textarea` и `contenteditable` глобальные action-shortcuts не срабатывают, кроме явно разрешённых `Cmd+K` и переходов по задачам. Терминал сохраняет собственные сочетания; Clew перехватывает только зарегистрированные глобальные комбинации.

На первом этапе нельзя полагаться только на сочетания браузера. `Cmd+1…9` обычно переключает вкладки, а `Cmd+0` сбрасывает zoom; браузер может не отдать их странице даже при `preventDefault`. Перед реализацией нужен короткий spike в поддерживаемых Safari/Chrome/Firefox и в standalone/PWA режиме. Рекомендуемый fallback для browser-hosted UI — `Option+1…0`, при этом `Cmd+1…0` остаётся целевым сочетанием для desktop/standalone surface.

## Этапы реализации

1. Ввести единый shortcut registry, scope rules и тесты конфликтов с inputs, модалками и xterm.
2. Добавить `Cmd/Option+1…0` и визуальные номера в sidebar; проверить текущие фильтры, сортировку и менее десяти задач.
3. Привязать `Cmd+Enter`, `Cmd+E`, `Cmd+Shift+E`, terminal shortcuts к существующим UI actions без дублирования command logic.
4. Добавить hold-Command overlay, reset на blur/visibilitychange и справку в command palette.
5. Провести ручную проверку macOS keyboard layouts, VoiceOver, Safari/Chrome/Firefox и active embedded terminal.

## Критерии готовности

- Shortcut и клик вызывают один и тот же handler и дают одинаковую диагностику.
- Быстрое повторение клавиши не создаёт дублирующих command requests.
- Нумерация всегда совпадает с видимым порядком задач.
- Терминал и поля ввода не теряют обычные клавиши.
- Key hints не вызывают layout shift, не остаются после blur и читаются средствами доступности.
- Внешние действия учитывают controller-local/runner-local и capability выбранного plugin adapter.

## Открытое решение

Нужно выбрать политику для browser-hosted UI: показывать `Option+1…0` как основной рабочий shortcut уже сейчас или считать `Cmd+1…0` требованием будущей desktop/standalone поверхности и оставить навигацию через `Cmd+K` в обычной вкладке браузера.
